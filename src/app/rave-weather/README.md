# Rave Weather — TranceWeekend

Open `/rave-weather` after `npm run dev`. The existing news site stays at `/`.

## Installation

- Use Chrome on an HTTPS site (localhost works on the installation computer).
- Connect a webcam and frame one person's head and shoulders. Click **进入天气系统** to grant camera access. A large mirrored canvas preview applies a cyan-and-magenta soft-light treatment with up to five motion trails, chromatic separation, edge glow and signal-reactive particles. Shoulder and wrist landmarks drive energy rings, living electric arcs, wrist lightning and timed shockwaves while pose inference continues to read the unfiltered video. The preview, visual landmarks and final-frame snapshot stay in memory and are never included in the saved result. The 42-second sequence begins after camera permission is granted and does not wait indefinitely for a perfect pose lock.
- After the camera is ready, the browser separately requests microphone access. An in-browser analyser detects low-frequency onsets and estimates tempo without recording or uploading audio. If microphone access is denied or the signal is weak, a 120 BPM visual pulse keeps the experience running.
- **不用摄像头，先试玩** runs an explicitly labelled demo. Pointer speed controls movement, horizontal position controls expansion, vertical position controls pressure. Touch dragging also works.
- Choose WARM UP / DEEP / BUILD / PEAK / CLOSING with the bottom-left control before a session. Sound is opt-in from the top-right. Fullscreen is in room settings.
- The full experience lasts 42 seconds: recognition 0–3s, shoulder release 3–11s, movement 11–20s, opening 20–29s, a free final surge 29–34s, and an eight-second dissolve reveal from 34–42s. Each challenge locks after its target is held for 0.7 seconds and responds with a status stamp and a dry joke; missing a target never pauses or blocks the timeline. Visual and optional audio intensity rise through all four stages, and the final five seconds add a large countdown. At 34 seconds the last preview frame is captured and all media tracks stop. The snapshot dissolves into its result-specific material—lightning and rain, aurora beams, pressure fog, glitch vortices or refracted monsoon water—before the conflict copy and result name appear. If capture fails, the same weather timeline continues without the portrait. Once the camera is ready the clock does not pause when tracking briefly drops; early completion plays the same complete eight-second reveal.
- Shoulder drops, wrist sweeps, body opening and high-energy surges create gesture events. Events less than 1.4 seconds apart build combo tiers at ×2, ×4 and ×8; actions within 180ms of a detected beat receive an `ON BEAT` boost. Each session can reveal one deterministic hidden system event.
- Eight normalized motion points are sampled at 8fps. The best four-second window is quantized, reduced to 4fps when needed, and stored in the anonymous seven-day result. Raw body proportions, camera frames and audio are excluded. The trajectory stays invisible and controls weather speed, direction, coverage and intensity.
- A result carries averaged visual signals, a random seed, phase, timestamp, bilingual name, Chinese punchline, conflict copy and an optional visual kind. Twelve common weather definitions use weighted signal matching; ON-BEAT AURORA, DANCEFLOOR SUPERCELL and ARTIFICIAL SUNRISE are performance-triggered rare results. Older links derive the visual kind from their English name or signals. Reveal, stable result, highlight replay, video export and PNG poster all use the same seed-driven renderer.
- New results create an anonymous 12-character short link containing validated weather parameters and a quantized motion trajectory. The record expires after seven days. It never contains a name, account, photo, source video, audio or raw body proportions. If the short-link service is unavailable, QR creation falls back to the compact `rw2` URL fragment. For phone scanning, deploy this application to HTTPS and enter that origin in room settings when operating from localhost.
- The primary share artifact is a 720×1280, 25fps, four-second pure-weather film. Weather fills the frame and no body, skeleton or motion line is drawn. The PNG fallback is taken from the same climax composition and neither artifact contains a QR code.
- The installation home screen preheats the local pose model and WASM, then enters a silent attract loop after eight idle seconds. After the 42-second experience, the result receives four seconds alone before a large QR code appears for 35 seconds. Opening the phone page claims the weather; the projector confirms receipt and returns to the attract screen after six seconds. With no scan it resets when the 35-second window ends. The phone continues generating independently and offers one-tap system sharing or a direct download.

## Event operation

- Run `npm run build && npm start` on the installation computer and open `http://localhost:3000/rave-weather` in Chrome. Set `NEXT_PUBLIC_SITE_URL=https://observatory.tranceweekend.com` or enter that address once in room settings so QR codes remain public.
- Before doors open, grant camera and microphone permissions, confirm all four setup indicators, complete one camera session, scan its QR code on a phone, and switch the browser to fullscreen.
- The local installation continues when venue internet drops after its assets are cached. Phone QR results still require the public Vercel deployment to be reachable.

## Boundaries and field testing

This is an MVP, not a validated measurement system. Signals represent body geometry and motion, never mental states. No face recognition, identity tracking, expression classification or camera recording is performed. The MediaPipe lite pose model and matching WASM runtime are served locally from `public/rave-weather`; model loading needs no third-party request.

Real camera tracking, low light, full-body framing, latency and projector performance require venue testing. Inference is throttled to about 15fps; no sub-100ms guarantee is made. Head direction and facial signals are not separately classified. Highlight export prefers MP4, falls back to WebM, and uses the PNG poster when recording is unavailable. The animated mobile result remains procedural. Branding uses TranceWeekend / Beijing.

Model source: https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_lite/float16/1/pose_landmarker_lite.task
Runtime: @mediapipe/tasks-vision (see package-lock.json). If upgrading the runtime, recopy its wasm directory to public/rave-weather/wasm.

Validation: `npx tsc --noEmit`, `npx eslint src/components/rave-weather src/app/rave-weather src/app/api/rave-weather`, `npm run build`. Browser smoke checks cover the fixed 42-second duration, combo decay and tiers, fallback beat pulse, four challenge locks, final-five-second countdown, the eight-second dissolve stages, early completion, media-track release, the four-second pure-weather film, PNG climax-frame fallback, seven-day short links, claim/status APIs, projector claim polling, unattended reset, old long links and compact `rw2` reconstruction, sound on/off and responsive overflow. Real body tracking, microphone beat accuracy and native sharing remain venue acceptance checks.
